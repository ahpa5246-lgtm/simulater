# Component illustrations (v0.4)

All existing sensor inputs, board families, circuit-component families, output demonstrations and instrument panels have local SVG artwork. The 33 assets are original drawings generated by `scripts/build_part_art.py`; no Fritzing images, application code, logos or proprietary device artwork are bundled. The artwork is dedicated to CC0 in `web/parts/LICENSE.txt`. This dedication covers these illustrations only; it does not change the application's license.

Open **Component gallery** from either workspace. Search by component name/category, inspect model status and select supported sensors or boards. Circuit components can be selected for placement from the gallery or the illustrated component palette. Planned boards remain visual-only and cannot be executed.

In the circuit workspace, **Component images** switches the same circuit to recognizable illustrations. Existing pin endpoints, wires, rotation, values, undo and ngspice netlists are retained. **Schematic symbols** returns to the schematic view. This is an illustrated connection view, not a solderless-breadboard connectivity engine or exact physical assembly layout.

The board workspace displays the selected board and sensor illustration, connector names, signal/power wires, disconnected-state dashed lines, and the CPU-observed onboard LED state. Gold connectors can be clicked or keyboard-activated to inspect their assigned signal. Board wiring remains the documented preset (A0, D2/D3 or A4/A5); clicking a connector inspects it rather than rewiring it. Family illustrations are not dimensionally accurate hardware footprints. Check the manufacturer's pinout before building physical hardware.

Servo and buzzer artwork represents existing PWM/tone examples. It does not add motor mechanics or sound synthesis. Digital sensor artwork likewise does not change the existing ideal behavioral-model assumptions. USB, antenna, chip and PCB details are illustrations, not additional emulated peripherals.

## Verification

`node tests/parts-browser.cjs` loads every asset, selects all 12 sensor illustrations, checks pending-board gates, selects a sensor from the gallery, exercises connector inspection, executes actual HC-SR04 firmware, and verifies ngspice output across illustrated/schematic views and rotation. Existing circuit, board and instrument browser suites remain applicable. `python scripts/build_part_art.py` deterministically regenerates the artwork and connector inventory.

Visual reference: [Fritzing's project-view documentation](https://fritzing.org/learning/get-started/project-view), reviewed 2026-10-23. The recognizable-parts palette and separate symbol/image views informed this interaction; no Fritzing compatibility or complete feature parity is claimed.
